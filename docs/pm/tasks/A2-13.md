## 这条任务是怎么来的，和 A2-12 的关系

A2-09（PR #119，已合入）把 KDA 反向的九个 kernel + `kda_bwd_stable` 单元原样移植到 A2；A2-12
（PR #132，已合入）做了前向（`kda_fwd_stable`）的真实形状 + 门控跨度重测，并**明确把
`CAPABILITIES["a2"]["qualified"]` 留成 `False`**——原文："公共 dispatch 尚未接线，保留未验收
总开关"，PM 在评审中确认这个边界（`ascend_fla/platform.py` 现在的 `evidence` 字段写着同一句话）。
`max_gate_span["stable"]` 目前只有 `forward: 158.0`，没有 `backward` 键——这正是本任务要填的。

A2-13 是反向这一半的对应任务，同样应该保持"单元级资格化"这个已确立的范围边界，**不是**把
`ascend_fla.ops.kda`（A5 上已经在用的、SoC 泛化的公开 autograd 接线——见 `ascend_fla/ops/kda/
{chunk,chunk_bwd,autograd}.py`，通过 `resolve_soc`/`device=` 参数泛化，理论上已经能指向 a2）
的 `qualified` 开关翻成 `True`。**`qualified` 翻转是 PM 审过两个方向（前向 A2-12、反向本任务）
之后才做的最后一步，不是 assignee 自己判断的时机**，同 A2-12 已经写明的纪律。

## 关于范围的裁定（回复申领人两轮预检提出的问题）

申领人的预检（见 A2-13 board reports）准确指出一个真实的精度契约缺口：`kda_bwd_stable` 的
`reference.py:69-114` 用**独立算出的 FP32** 数学构造九个检查点 fixture，而真实前向
`kda_fwd_stable/kernels/wy.py:116-144`、`recurrent.py:126-179` 在多处把中间量舍到 BF16——
**两者不逐位相同**，用 fixture 校验反向单元，测的是"反向数学对不对"，不是"反向单元接真实前向
产出的缓存对不对"。这是本任务方法论要修正的地方，不是要因此把范围升级成"真实带缓存前向 + 公开
autograd 接线"：

- **不升级范围**：A5 的 `ascend_fla/ops/kda/chunk.py::chunk_kda_fwd_with_caches` 与
  `chunk_bwd.py::chunk_kda_bwd` 都在入口调用 `require_qualified(device)`——即便这两个函数本身已经
  是 SoC 泛化的（走 `resolve_soc`/`device=` 参数），指向 `device='a2'` 时也会因为
  `CAPABILITIES["a2"]["qualified"]=False` 直接报错。这个门是故意的（`AGENTS.md` §7），本任务的
  写集也没有 `ascend_fla/ops/kda/*.py`，**不能靠改这些文件绕开**。
- **但要用真实缓存，不是独立 fixture**：正确做法是走 A2-03/A2-12 已经在用的技术——**绕开门控的公开
  包装函数，直接对 ascriptor 单元发起调用**（`kernels/projects/a2/kda_fwd_stable` 先跑一遍真实前向，
  拿到真机产出的九个检查点；这九个值再喂给 `kernels/projects/a2/kda_bwd_stable` 的真机调用）——这
  仍然是"单元级"（不经过被 `require_qualified` 挡住的公开入口），但缓存内容是**真实**的，不是
  fixture 构造的。九个检查点的名字与组装方法（六个直接来自前向 kernel 输出、`g_cumsum=log2(eg)`
  另算、`h`/`v_new` 由 `_scan_states` 补）**可以直接参照** `ascend_fla/ops/kda/chunk.py` 里
  `chunk_kda_fwd_with_caches` 的文档字符串与实现（**只读参照/复用其中不带门控检查的纯数学部分，
  例如 `_scan_states`——它本身不调用 `require_qualified`，可以直接 import 复用；带门控检查的部分
  不要复用，写测试自己的、对 a2 直接发起 ascriptor 调用的等价逻辑**）。
- **精度判定升级为"端到端"**：拿到真实缓存后，反向单元产出的 `dq/dk/dv/dg/dbeta/dh0` 不再对着
  独立 FP32 fixture 的"期望输出"比，而是对着**CPU FP32 端到端参考**（pin 住的 fla naive KDA 或
  本仓 `ascend_fla/reference/kda.py`，对完整 前向+反向 组合用 `torch.autograd.gradcheck`-风格的
  自动微分产出梯度）比相对 L2——这样"真实前向的 BF16 舍入接缝"这件事在两边都是一致的输入，不会
  出现"反向单元本身对、但接不上真实缓存"这种测不出来的缺口。
- `reference.py` 里现成的独立 FP32 fixture 构造**可以留着**，但测试报告里要明确标注它是"反向 kernel
  孤立数学正确性"的检查，不能被当成"反向单元接真实前向缓存后的精度结论"——两件事分开报数字，不要
  合并成一个"通过"。

**`qg` 缩放陷阱**（申领人已指出，写进来避免重复踩）：反向需要**未缩放**的 `qg`
（`kda_bwd_stable/reference.py:107`，对应前向 `wy.py:113-115,128`）；`kda_fused_recurrent` 单元的
`recurrent.py:133-142` 存的是 `qg*scale`（decode 用的环形缓冲，不是本任务要用的东西）——组装九个
检查点时只从 `kda_fwd_stable`（chunk 前向单元）取 `qg`，不要碰 `kda_fused_recurrent` 内部状态，
两个单元的 `qg` 不能混用。

## 关于测试夹具组装的裁定（2026-09-28，回复申领人 RISK contradicts-handoff，issue #40 评论 5875719287）

申领人读源码发现一处本规格没预料到的真实差异，**不是争议，是有效的新发现，裁定直接采纳**：

- **A2 前反向两个单元的张量布局不兼容，`HV>1` 时不是 view 能解决的**——`kda_fwd_stable/unit.py:
  116-124` 的六项直接输出是连续 `[B,HV,C,64,D]`（chunk 分块、head-major），`kda_bwd_stable/
  unit.py:52-64` 要求连续 `[B,T,HV,D]`（token-major），`T=C*64`。两个布局之间要一次真正的
  permute+reshape，`HV>1` 时不能只靠 `.view()`。
- **不能复用 `_from_bhcld`/`_layout_runtime`**：PM 已读源码确认
  `ascend_fla/ops/kda/chunk.py::_layout_runtime()` **硬编码**路径
  `kernels/projects/a5/kda_layout/runtime.py`（不是按 `device` 参数化的），复用它会在 a2 上悄悄
  跑 a5 的布局 kernel，是错的——申领人自己也已经判断出这一点，不要用。
- **裁定：允许测试夹具做这次布局转换，但有五条边界**：
  1. 只能出现在本任务的测试代码里（当前写集），绝不碰 `ascend_fla/ops/kda/*.py` 或任何产品
     runtime 路径。
  2. 不复用 `_from_bhcld`/`_layout_runtime`，为 a2 单独写等价的测试侧转换。
  3. 转换本身用 NPU 原生 torch（`permute().contiguous()`，这台真机是原生 910B、算子包齐全，
     跟 `AGENTS.md` §5 描述的"缺 `ascend950` 算子包"那种边缘情况不是一回事）还是用
     D2H→CPU 重排→H2D，由 assignee 自行决定；两条路都允许，**如实报告选了哪条**。
  4. 转换前的六项原始设备输出哈希、转换后的九项检查点哈希、每一步的来源，**都要分别报告**（申领人
     自己提的口径，采纳）。
  5. 测试报告里必须把这一步明确标注为"测试夹具组装成本"，不得声称是零拷贝或产品路径的性能特征——
     这不是给 `D-PM-35/37` 开口子：那条纪律管的是 `ascend_fla.ops.kda` 公开入口与它的 runtime，
     本任务的写集本来就没有那些文件；测试夹具为了桥接两个独立调用的单元做一次有名有据的布局转换，
     跟"公开入口悄悄在 host 侧做算术"是两回事，只要如实报告就不违反纪律的本意。

另外两点申领人的源码核实，**采纳，不是新问题，供后续读者对齐**：`chunk.py:798-803` 的 stable 分支
是直接对 `g_cumsum` 做 FP32 乘 `1/ln2` 再窄化，不是按 `chunk_kda_fwd_with_caches` 文档字符串字面
写的"`g_cumsum=log2(eg)`"反推（后者在宽域下 `eg` 会下溢到 0，`log2(0)` 是坏路径，stable 分支正是
为了避开这条）——组装真实检查点时以实际代码为准，不要照文档字符串的字面描述另算一遍；`qg` 的真实
位置是 `kda_fwd_stable/kernels/recurrent.py`（不是 decode 单元 `kda_fused_recurrent`），申领人已
确认会取这里的未缩放 `qg`，与 §"关于范围的裁定"一节的 `qg` 陷阱提醒一致。

## 范围

1. **真实缓存组装**（先做这步，是后面两项的地基）：写一个 a2 专用的辅助（测试代码内，不进
   `ascend_fla/ops/kda/`），直接对 `kernels/projects/a2/kda_fwd_stable` 发起 ascriptor 调用（同
   A2-03/A2-12 的技术），产出真实的九个检查点（`BWD_CACHE_NAMES` = `g_cumsum, Aqk, Akk, w, u, qg,
   kg, v_new, h`，参照 `ascend_fla/ops/kda/chunk.py::chunk_kda_fwd_with_caches` 的组装方法，
   `_scan_states` 可直接 import 复用；**布局转换按上面"关于测试夹具组装的裁定"一节执行**，不要
   复用 `_from_bhcld`/`_layout_runtime`）。用小形状先验证这一步本身正确（六个直接量与真实前向
   单测的已知输出核对、`g_cumsum`/`h`/`v_new` 三个 host 补算量对独立 FP32 参考核对）。
2. **反向单元接真实缓存**：把上一步的九个检查点喂给 `kernels/projects/a2/kda_bwd_stable` 的真机
   调用，`dq/dk/dv/dg/dbeta/dh0` 对 CPU FP32 端到端参考（fla naive KDA 或
   `ascend_fla/reference/kda.py`，前向+反向整链自动微分）报相对 L2，预算沿用 A5 契约的 `0.05`
   （A2-09/A2-12 用的同一个数，不新定）。真实 Kimi-Linear 形状（`H=HV=32, K=V=128`，`T` 取
   `L_PER_CHUNK` 整数倍，至少 64/128/512/4096 各一个）与 `(C,HV)` 边界点（`HV=32`、`C=1`，参照
   A2-12 已更正的"C=1 且 HV=32 不预期报错"的结论）都要覆盖。
3. **独立 fixture 的孤立数学检查**（保留，但明确标注口径）：`reference.py:69-114` 的独立 FP32
   fixture 路径继续作为"反向 kernel 孤立数学正确性"检查跑一遍，测试报告里与第 2 步的"真实缓存端到端"
   结果分开报，不合并陈述为同一个"通过"。
4. **门控跨度重测（backward）**：方法论同 A2-12（`AGENTS.md` §6"按量程失效的缺陷"/"闸是双边约束"），
   阈值必须在 A2 上重测，不能抄 A5 的 105：
   - 用第 1 步产出的真实缓存（而不是独立构造的跨度探针）在 `H=HV=32` 真实形状下扫 `gate_span`，
     每个点分开报"有限"与"在预算内"两件事（同 A2-12 的方法论）。
   - 上边界：预算仍然成立的最深实测点，留安全边界（参照 A5 169.8 有限性 vs 105 精度预算的留白比例，
     具体数字由实测决定）。
   - 下边界：fla 默认初始化在真实 `HV=32` 形状下、≥8 个随机种子的跨度分布上界。
   - 闸最终定成 `min(上边界所有安全点)`；`max_gate_span["stable"]["backward"]` 写进
     `ascend_fla/platform.py`。
5. **`CAPABILITIES["a2"]` 填数**：本任务完成后，`max_gate_span["stable"]` 补上 `backward` 键；
   `qualified` 仍留 `False`（PM 审过两个方向都过了才改，不是 assignee 自己翻）。

## 已知陷阱

- **不要把独立 FP32 fixture 的"通过"当成"接了真实缓存也通过"**——这是本任务存在的理由，见上面
  "关于范围的裁定"。
- **`qg` 只从 `kda_fwd_stable` 取，不要碰 `kda_fused_recurrent` 的 `qg_ws`**（缩放不同）。
- **不要试图翻 `qualified`**——写集里没有那个权限，PM 会在两个方向（含 A2-12 已完成的前向）都审过
  之后才改。
- **不要把 A5 的 105 当起点去试探**——A2 的跨度上限可能比 105 大也可能小，两个方向都要留证据。
- A2-11 的新约束适用：验证中若发现 BF16/FP16 `splitk` 在 `M<64` 的路径，按 §7 必须报错，不能绕过。
