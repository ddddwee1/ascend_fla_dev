## BF16 整网验收：模型质量评测（2026-10-25 批准，源自 issue #146）

张量级 BF16 整网相对 L2 超预算，但这个数字本身不直接等价于任务质量受损——下游任务只用
到 logits 的相对排序，不要求逐元素接近参考。用户 2026-10-25 批准按 issue #146 的方案推进，
**把模型级质量指标作为 BF16 整网的主验收判据**，原有算子级硬闸（FP32 双 oracle 契约、
跨 bd 逐位、FP32 整网 1e-3）不变、不放宽；旧的 BF16 张量 1e-2 失败回执继续保留作为诊断，
不代表通过。

**对照组**（独立进程，同卡健康检查）：
- A = Torch FP32（dtype 变化的参照零点，报告但不参与门槛判定）
- B = Torch BF16（原生实现，主对照的参照）
- C = BF16 chunk prefill + 现有 CCE recurrent decode（本任务候选，**B→C 隔离"实现替换"
  这一个变量**；A→B 单独报告"精度变化"，A→C 报告两者叠加的总变化——三者不得混在一起说）

**数据/模型/评分身份**（正式评测前全部冻结，变了就是另一次评测）：
- 模型：`docs/matrix/models.json` 的 `gdn2-1.3b-fineweb-edu-100b`，
  checkpoint SHA256=`4ac729c627febc431bf4b2011a9cb7ad9c30cc1d017ff74aeca15f76efb2df6d`
  （来源 https://huggingface.co/LLM-OS-Models/gdn2-1.3B-fineweb-edu-100b ，
  revision=`86327354dd1e6874fe6407878087079326fee851`）。
- tokenizer：`TinyLlama/TinyLlama_v1.1`，revision=`ff3c701f2424c7625fdefb9dd470f45ef18b02d6`，
  vocab=32000，核验文件 SHA 与 BOS/EOS 规则。
- 数据：`Salesforce/wikitext`（`wikitext-2-raw-v1`，test split）与 `Rowan/hellaswag`
  （validation split），评分规范固定 `EleutherAI/lm-evaluation-harness` 的对应 commit——
  revision/SHA 在正式评测前冻结，pilot 不得反向用来挑阈值或挑有利样本。

**验收判据**：
1. **算子正确性硬闸不变**：FP32 双 oracle 契约（relL2≤1e-4 + 既有 allclose）、跨 bd 逐位、
   有限性/shape/dtype、cache offset/state 交接检查；FP32 整网 1e-3 门槛不变。
2. **语言模型质量（主判据之一）**：WikiText-2 raw-v1 test 全量，context∈{1024,4096}，
   stride=512，重叠目标只计分一次，报 sum_nll/有效 token 数/NLL per token/PPL。
3. **下游任务质量（主判据之一）**：HellaSwag validation 全量 zero-shot，固定 EleutherAI
   任务定义复现 prompt 与 acc/acc_norm，报样本数与逐题配对结果。
4. **stateful 路径**：固定真实前缀，prefill 后用真值 token 连续 decode 64 步（覆盖总
   context 1024/4096），对尾部 token 计 NLL——覆盖 cache 交接，不依赖自由生成文本是否相同；
   记录各层 state/conv cache 的有限性、offset 与 L2 诊断。
5. **容差（冻结）**：C 相对 B 的 PPL 增幅 ≤1%；HellaSwag acc_norm 下降 ≤0.5 个百分点。
   两者都用配对 bootstrap 报单侧 95% 退化上界，**上界必须落在容差内才算通过**；样本不足
   或区间跨门槛记为"不确定"，不当通过。
6. 所有组报告 logits/cache 的 relL2/max_abs、有限性、route_counts、checkpoint/dtype/环境
   身份；质量指标不能代替算子契约，也不能凭小样本或"无显著差异"就宣称等价。
7. 评测/计分代码自带有效 token 计数、滑窗 mask、候选评分、state offset 的 CPU 正负对照；
   真机回执给逐文档/逐题配对数据和原始摘要，原始日志/数据/快照只进 `tmp/`（git-ignored），
   不提交二进制或机器信息。

## 已知陷阱

- **A5 profile 声明的 32 cube / 64 vec 与 Ascend950PR 物理的 28 cube / 56 vec 不一致**
  （AGENTS.md §5）；`block_dim` 超物理核数会在硬件 barrier 上死锁，先查这台机器的
  opp 算子包普查表再定 `block_dim`。
- 共享机器：先看 `npu-smi info` 的 Health 列，别 kill 或改别人的进程。
- 跨步视图的 D2H 在缺 `ascend950` 算子包的机器上要先整块 D2H 再切片（AGENTS.md §5 那条
  "先整块 D2H 再切" 的陷阱，C=1 时最容易只测到"恰好也过"的假阳性）。
- 这台机器上测的数字不能替另一台 A5 机器代言——每台单独测。
