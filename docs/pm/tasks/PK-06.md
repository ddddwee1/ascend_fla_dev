## 这条任务是怎么来的，和 GDA-04 的关键区别

D-PM-22 排期里 decode 阶段的第三个切片（GDN → 已完成，PGDN 接在后面）。来自 #89（外部需求，分诊后
采纳，用户批准）。

**PK-06 比 GDA-04 多一层复杂度：两个独立递推状态。** GDN decode 只有一个 `[B,HV,128,128]` 主 state；
PGDN 还有一个 `[B,H,128]` 的 ATK 对角预条件状态（`A`），归属按 `H`（key 头），**不随 `HV` 复制**——
GVA 分组下同组的多个 value 头共享同一个 key 头与同一个 ATK state，这是 PGDN 特有的、GDN 没有的耦合。
写代码和测试时把这两个状态当成两条独立的递推链看待，不要因为都叫"state"就合并处理。

`fla` 对应实现是 `fla.ops.precond_gated_delta_rule.fused_recurrent_precond_gated_delta_rule`
（Triton kernel，语义权威参照，不执行——同 GDA-04 的口径，见下方 oracle 一节）。

## 现有 PGDN chunk 前向 ABI（只读参照，不是要复用的代码；PM 已读 `ascend_fla/ops/pgdn_chunk_fwd.py`
与 `kernels/projects/a5/pgdn_chunk_fwd/contract.json` 源码核实，行号/字段以当前 main 为准）

`chunk_pgdn(q,k,v,g_atk,g,beta_atk,beta,*,scale=None,initial_state=None,initial_A_state=None,
output_final_state=False,use_qk_l2norm_in_kernel=True,x=1.5,eps=1e-6,log_atk_scale=None,...)`：

- `q,k`: `[B,T,H,128]`；`v`: `[B,T,HV,128]`；`g,beta`: `[B,T,HV]`（主 state 的标量门控/更新率，同 GDN）；
  `g_atk,beta_atk`: `[B,T,H]`（**ATK 状态自己的标量门控/更新率，按 H 不按 HV**——四个门控张量两两
  形状不同，接线时最容易混）。
- `q/k/v` 同为 FP32 或 BF16；`g/beta/g_atk/beta_atk` 恒 FP32。
- `scale` 固定 `128**-0.5`；`x` 固定 `1.5`；`eps` 固定 `1e-6`（这是 ATK 平方-压缩用的 epsilon
  `log(A+eps)`，**不是**归一化用的那个 `1e-12`，两个 eps 不同来源、不同量级，别混）；`log_atk_scale`
  固定 `-0.2`（即压缩中心 `center`）；`use_qk_l2norm_in_kernel` 必须为 `True`——这四项 chunk 侧都是
  常量，非此值直接报错，**decode 沿用同一组常量**，不开放成可配置参数（除非真机测出需要，先发 RISK
  不要自行放开）。
- `T` 必须是 64 的倍数、`≤4096`；`HV % H == 0`（GVA 分组，同 GDN/KDA 的约定）；GVA 下 `q,k,g_atk,
  beta_atk` 按 `repeat_interleave(n_rep, dim=head)` 展开对齐 `HV`，但 **ATK state 只保留每个 key 头
  一份**（不展开存储）——`naive_recurrent_precond_gated_delta_rule` 返回 `final_A_state` 前做
  `A = A[:, ::n_rep]` 正是这个收缩，decode 的 ABI 要对齐这个收缩后的 `[B,H,128]` 形状，不要因为
  kernel 内部计算时展开过就把公开 state 形状也做成 `[B,HV,128]`。
- **`initial_state`/`initial_A_state` 现在都只接受 `None`（零初始态），传张量直接报错**——chunk 前向
  不支持非零初始 state（两个状态都不支持，不只是主 state）。这意味着"chunk→decode 续接"的验证只能是
  单方向：chunk 从零开始跑一段前缀产出 `final_state`/`final_A_state`，喂给**本任务的 decode**继续
  递推；不能反过来验证 decode 的 state 喂回 chunk。
- `final_state`：`[B,HV,128,128]` FP32，K 在前，与 GDN chunk 的布局一致。`final_A_state`：
  `[B,H,128]` FP32。本任务的 `initial_state`/`initial_A_state`/两个输出 state 必须用同一套布局，
  否则 prefill→decode 接不上。
- 归一化：`x/max(norm(x),1e-12)`（乘性，literal naive 语义），**不是** fla Triton fused_recurrent
  用的加性 epsilon `x/sqrt(Σx²+1e-6)`（PM 2026-09-19 已读 `precond_gated_delta_rule/fused_recurrent.py:
  130-132` 核实分叉）。chunk 侧的入口文档字符串已经把这条写死为 kernel 内部行为并加注释说明分叉原因；
  decode **必须显式保持同一套乘性归一化**，不得静默切到 fla fused_recurrent 的加性语义——要切换需用户
  另行决定，不是 assignee 自行判断。
- `head_first` 不支持，`launcher` 只认 `inprocess`/`aclnn`/`board`；varlen/context parallel 不支持。

## 范围

1. **域声明与 ABI 冻结**（先做这步，再动手，`AGENTS.md` §7）：
   - 公共入口 `fused_recurrent_pgdn(q, k, v, g_atk, g, beta_atk, beta, *, initial_state=None,
     initial_A_state=None, output_final_state=False, scale=SCALE, x=1.5, eps=1e-6, log_atk_scale=None,
     device='a5', block_dim=?, ...)`，形状/dtype 逐项对齐上面的 chunk ABI 表（S 换成短步数，不要求
     64 的倍数——decode 场景 S 很小，允许 `S=1..S_MAX`，`S_MAX` 由 kernel 内部缓冲行数决定，参照
     KDA/GDN decode 的先例，具体数字由实现定并写进 ABI 冻结表，不要凭空假设）。
   - `initial_state`：**必须支持非零**，`[B,HV,128,128]` FP32，K 在前，与 chunk 的 `final_state`
     布局一致。`initial_A_state`：**必须支持非零**，`[B,H,128]` FP32，与 chunk 收缩后的
     `final_A_state` 布局一致。两者各自 `None` 表示零初始态，**可以独立传（一个 None 一个非 None）**
     ——不要假设两个状态必须同时有初值或同时为零，除非真机测出必须绑定，先发 RISK 说明理由。
     `output_final_state=True` 时返回更新后的两个同形状 state（新张量，不原地改 `initial_state`/
     `initial_A_state`）。
   - `block_dim` 的合法取值**由实测决定，不假设等于 chunk 的 `{1,2}`**（同 GDA-04 的先例：decode 走
     纯向量核，物理核数上限与 chunk 不同）。
   - **BF16 不需要显式拒绝**——`q/k/v` 原生支持 BF16 或 FP32（同 chunk），dtype 转换全部在 kernel 内
     完成（D-PM-35/37：host 侧只做校验/分配/launch，不做 `.float()`/`.to(dtype)`）。`g/beta/g_atk/
     beta_atk` 恒 FP32。**这条更正了旧骨架里"BF16 显式拒绝"的过期说法**——那是 PK-03/PK-05 时期 BF16
     kernel 还没做的临时限制，GDA-04 已证明 BF16 原生支持可行，PK-06 沿用同一路线；`board.json` 里
     PK-06 的 `dtype` 字段本来就同时列了 `["bf16","fp32"]`，与这条一致。
   - `x`/`eps`/`log_atk_scale`/`use_qk_l2norm_in_kernel`/`scale` 五个常量沿用 chunk 的固定值
     （见上一节），入口对非默认值报错，不开放成运行时可变参数。
2. **双 oracle**：**A** = pin 住的 fla `fla/ops/precond_gated_delta_rule/naive.py::
   naive_recurrent_precond_gated_delta_rule`（CPU FP32，原样加载、hash 核验，不改一个字；语义
   权威——PM 已读源码核实，见上）；**B** = 本任务独立写的 CPU FP32 逐 token 递推（不复用 A 的实现，
   不 import A，两个状态的更新顺序、GVA 展开/收缩都要独立写一遍，不能只在主 state 上独立、ATK 抄 A）。
   两者先用 FP64 抬升版本的 A（lifted，明确标注是抬升实现而非声称原始 naive 支持 FP64）与独立 FP64
   版本的 B 互相对照，证明 A、B 自己是对的，再往下走（同 GDA-03/GDA-04 口径）。
   `precond_gated_delta_rule/fused_recurrent.py` 只作分组/布局/默认 flags 的语义参照，**不执行**（纯
   Triton kernel，执行了就违反"不声称 CUDA/Triton"）。
   **FP64 lift 比 GDN 多两个节点，逐项核对，不要照抄 GDN 的两节点 lift 清单**（precheck 已读出的四处
   显式 FP32 dtype 节点，供起草 lift 清单参考，不是穷举，assignee 自己再读一遍源码确认）：
   ① 输入整体 `.to(torch.float32)`（`q,k,v,g_atk,g,beta_atk,beta` 的 transpose+contiguous+cast 一步）；
   ② 标量 `log_atk_scale` 分支的 `center = torch.tensor(log_atk_scale, dtype=torch.float32, ...)`；
   ③ 张量 `log_atk_scale` 分支的 `center = log_atk_scale.to(torch.float32).view(1,H,1)`（GVA 下这个
   分支还要过 `repeat_interleave`，本任务固定 `log_atk_scale=None`→`-0.2` 标量，理论上走不到这个
   分支，但 lift 清单里仍要写明"为什么排除"而不是漏提）；
   ④ `logx = torch.log(torch.tensor(x, dtype=torch.float32, ...))`。
3. **prefill→decode 一致性**（`AGENTS.md` §6 硬判据，GDA-04 已验证过同类模式，可以照抄测试结构，
   但这次要对两个状态分别做，不能只做主 state）：
   - 用 `chunk_pgdn` 跑一段前缀（长度取 64 的倍数，例如 128），`initial_state=None`、
     `initial_A_state=None`，拿到 `final_state`、`final_A_state`；
   - 把这两个 state 喂给 `fused_recurrent_pgdn` 继续单步/短步递推若干步；
   - 与"整段一次性用 `chunk_pgdn` 算完"（前缀+续接总长仍需 64 的倍数，例如凑到 192）的结果比对，
     `o`/`final_state`/`final_A_state` 三者**各自**相对 L2 报数，逐 token 报，不只报平均（`AGENTS.md`
     §6 的教训：state 漏传只坏前几个 token，平均会掩盖）；**ATK state 单独判定，不能因为主 state/`o`
     对了就假设 ATK 也对**——precheck 已指出小 `exp(g_atk)` 乘大 `A0` 仍可能有效量级，ATK 出错未必
     反映在 `o` 或主 state 上。
   - 另外验证"decode 分段调用 + 串接两个 state"与"decode 一次调用相同总步数"两种方式逐位或近似一致
     （同 GDA-04 的分段 vs 一次性对照）。
4. **bd / 分组网格**：
   - `block_dim` 网格扫描，确定安全集合，`bd` 之间输出必须逐位相同（`B*HV` 足够大才能真正压到切分
     逻辑，参照 §6 铁律，用真实形状或至少 `HV≥4` 的形状测，不要只测 `HV=1`）。
   - `HV/H` 分组比至少覆盖 `{1,2,4,8}`（同 GDA-02/03/04 的口径），含非对称 `HV≠H`；GVA 下确认
     `A[:,::n_rep]` 这类跨步收缩在 kernel 输出侧是**连续**的（precheck 提到的疑点，需要实测确认，
     不能假设——如果 kernel 直接输出跨步视图、host 又不能做跨步整理，按 `AGENTS.md` §5 的"先整块
     D2H 再切"纪律处理，不要先切再传）。
   - 数值量程：**非零初始 ATK state 会把量程界从零初态的 `A≤T` 变成 `A≤A0+t`**（precheck 已指出，
     这里只是分析、不是缺陷结论，assignee 需要用真实非零 `initial_A_state` 实测重新标定这条边界，
     不能沿用 chunk 阶段"零初态"下测过的量程表）；主 state 侧沿用 GDA-04 的量程复核方法（`g≤0` 只
     保证 `exp(g)≤1`，不保证递推稳定，更新矩阵含 `I-beta*k*k^T`，列进量程复核表）。
5. **精度预算**：FP32 判定，`o`/`final_state`/`final_A_state` 对 A、B 各自相对 L2 ≤ 1e-4（先在 CPU 上
   校准 A↔B 一致性，若二者自己就接近或超过这个数量级，先报 PM 调整，不能事后放宽，同 GDA-03/04 口径）。
   BF16 只作质量/存储边界检查（不设 FP32 级别的通过阈值），不放宽 FP32 预算。
6. **同卡测量**：三轮 baseline/candidate/baseline（不设速度门槛，如实标基线身份，同 GD2-02 最近踩的
   坑——baseline 必须是任务真正要比的那个东西，不是抄别的任务的口径）。
7. **入口门控**：范围外组合（不支持的 `block_dim`、形状不匹配、`initial_state`/`initial_A_state`
   形状/dtype 不对、常量偏离默认值、`head_first`、任何未声明的可选项）在
   `ascend_fla/ops/pgdn_fused_recurrent.py` 显式报错，测试覆盖每一条拒绝路径。

## 已知陷阱

- **不要把 GDN decode 的单状态 ABI 直接套过来**：PGDN 有两个独立递推状态（主 state 按 HV、ATK state
  按 H，GVA 下不展开存储），GDN decode 只有一个。接线、测试、量程复核都要对两个状态各走一遍，不能
  只做主 state 然后假设 ATK "应该差不多"。
- **`chunk_pgdn` 不支持非零 `initial_state`/`initial_A_state`**（两个都不支持）——decode 的验证链路
  只能是"chunk 从零起→decode 续接"，不能反过来。
- **`prepare()` 的 kernel 注册数**：chunk 前向一次注册 12 个 entry（FP32 六阶段 + BF16 六阶段）。若
  decode 是 typed 的 FP32/BF16 两个 entry，联合进程（同时要 prefill 和 decode 的场景）需要 14 个
  entry 全部在首次执行前编完，不能照抄 GDA-04（GDN，9-entry：GDN chunk 已有 entry 数 + 2 个 decode
  entry）的具体数字——GDN 与 PGDN 的 chunk 阶段本身 entry 数就不同。`prepare(decode=True)` 的实现
  要按 PGDN 自己的 entry 清单核实，写进 ABI 冻结表。
- **两个 eps 不要混**：ATK 压缩用的 `eps=1e-6`（`log(A+eps)`）和归一化用的 `1e-12`（`max(norm(x),
  1e-12)`）是两个不同来源、不同量级的常量，都固定、都不可配置，但接线时容易看串。
- `final_state`/`initial_state` 的 K-V 轴顺序：K 在前（`[B,HV,128,128]`），与 chunk 契约一致；
  `final_A_state`/`initial_A_state` 是 `[B,H,128]`（GVA 收缩后，不按 HV 展开）。接线时如果发现和
  这个不一致，先发 RISK 不要自己悄悄改布局。
- 机器与卡归 assignee 自己管理（D-PM-28）；真机证据一行不能少：SoC/CANN/算子包/原始日志/逐项数字。
- **写集扩展走标准流程**：证据/报告类路径（如需要独立的 `docs/research/` 子目录或
  `benchmarks/a5/evidence/`）不在当前写集里，需要就先发 `RISK write-set-expansion`，PM 查完冲突
  批准后再用——GDA-04 踩过"临时才发现要改写集外文件"的坑，能提前想到的就提前在 ABI 冻结阶段一并申请。
